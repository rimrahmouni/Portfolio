Supervision de température sur plusieurs zones

Des ESP32 mesurent la température de plusieurs zones. Node-RED reçoit, par MQTT, les messages des zones A et B, les décode en JSON, les traite et les enregistre dans un fichier CSV. Il affiche aussi en direct l’évolution de la température et une jauge pour la zone B.

Le projet est un réseau de trois ESP32, avec transmission vers le cloud et traitement de la base de données.

  • MQTT
  • Node-RED
  • JSON
  • CSV

SMT Monitoring System

Application de bureau développée pendant mon stage ingénieur chez GDS (Global Display Solution), à Mornaguia, une usine d’assemblage de cartes électroniques. Les machines Pick & Place rejettent des composants, et les opérateurs ne déclarent pas ce rejet de façon fiable.

L’application calcule le rejet théorique sans dépendre de leur déclaration : l’opérateur scanne le NI de chaque bobine avant de la consommer, et le responsable suit la production en temps réel.

Deux espaces protégés : le responsable gère les ordres de fabrication, les nomenclatures (BOM), les bobines, les rejets et les rapports Excel ; l’opérateur scanne à la douchette USB et consulte alertes et état.

Dashboard énergétique et prédiction de consommation

Application web interactive qui analyse la consommation électrique mensuelle de maisons : indicateurs clés, histogramme mois par mois et répartition par appareil.

Un modèle d’IA complète le tableau de bord : il prédit la consommation jour par jour.

Sur les données analysées, la consommation totale atteint 324,76 kWh. La climatisation (23,9 %) et le chauffage (23,5 %) représentent à eux deux près de la moitié de la consommation.

Détection de fumeurs (YOLOv8)

Un modèle de classification YOLOv8 (yolov8n-cls) apprend à distinguer les images « smoking » et « not_smoking ». Le script prépare d’abord un sous-ensemble du jeu de données Kaggle, tiré au hasard, puis entraîne le modèle sur des images de 160 pixels pendant 10 époques.

Le modèle entraîné est ensuite utilisé en temps réel sur la webcam avec OpenCV : chaque image affiche la classe prédite et son score de confiance, et la touche q arrête le programme.

  • Python
  • YOLOv8
  • Ultralytics
  • OpenCV
  • Vision par ordinateur
1. Préparation du jeu de données
import os
import shutil
import random

base_path = r"chemin\vers\proj2"
new_base = os.path.join(base_path, "mini_projet2")

def create_dir(path):
    os.makedirs(path, exist_ok=True)

create_dir(new_base + "/train/smoking")
create_dir(new_base + "/train/not_smoking")
create_dir(new_base + "/valid/smoking")
create_dir(new_base + "/valid/not_smoking")

def copy_subset(src, dst, n):
    files = [f for f in os.listdir(src)
             if f.lower().endswith(('.jpg', '.jpeg', '.png'))]
    random.shuffle(files)
    files = files[:n]
    for f in files:
        shutil.copy(os.path.join(src, f),
                    os.path.join(dst, f))

# TRAIN
copy_subset(base_path + "/data/train/smoking",
            new_base + "/train/smoking", 4000)
copy_subset(base_path + "/data/train/not_smoking",
            new_base + "/train/not_smoking", 4000)

# VALID
copy_subset(base_path + "/data/valid/smoking",
            new_base + "/valid/smoking", 800)
copy_subset(base_path + "/data/valid/not_smoking",
            new_base + "/valid/not_smoking", 800)

print("Mini dataset prêt ✔")

3. Détection en temps réel avec la webcam
import cv2
from ultralytics import YOLO

# Charger le modèle entraîné
model = YOLO(r"chemin\vers\runs\classify\train-5\weights\best.pt")

cap = cv2.VideoCapture(0)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    results = model(frame)
    probs = results[0].probs

    class_id = probs.top1
    conf = probs.top1conf.item()
    label = model.names[class_id]

    cv2.putText(frame, f"{label} {conf:.2f}", (30, 50),
                cv2.FONT_HERSHEY_SIMPLEX, 1, (0, 255, 0), 2)

    cv2.imshow("Smoking Detection", frame)

    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()

Apprentissage fédéré sur cartes

Au lieu de rassembler toutes les données au même endroit, chaque carte secondaire entraîne son propre modèle sur ses données locales. Une carte centrale coordonne l’ensemble.

L’intérêt de l’apprentissage fédéré est de garder les données sur chaque carte et de limiter les échanges réseau : on partage des modèles, pas des données.
